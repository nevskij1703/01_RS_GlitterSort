# Уровни и кривая сложности

Готовых уровней в игре **нет**. Каждый уровень собирается на лету под заданное число ходов. Всё живёт в блоке `[LEVELS]` файла `index.html`.

## Кривая

Сложность уровня — **рейтинг 1..10**: 1 = 3 хода в оптимальном решении, 10 = 24 хода.

```js
const CURVE_PREFIX = [1, 3, 3, 6];          // L1..L4 — разгон
const CURVE_CYCLE  = [4, 4, 7, 4, 4, 10];   // L5+ — цикл, повторяется бесконечно
```

Получается `1-3-3-6 | 4-4-7-4-4-10 | 4-4-7-4-4-10 | …` — два лёгких уровня, один потяжелее, два лёгких, один пиковый. Номер → рейтинг считает `Levels.ratingFor(n)`, конца у прогрессии нет.

## Пресеты рейтингов

`Levels.RATING_PRESETS` — сколько ходов должно быть в решении и на каком поле такой оптимум встречается. Пустая колба всегда одна, цветов ровно `sticks − 1` (каждый цвет = одна полная колба в решённом состоянии).

| рейтинг | ходов (цель) | поле (колб/слоёв) | лейбл игроку | бюджет генерации |
|---|---|---|---|---|
| 1 | 3 | 3 / 2 | Очень просто | 60 мс |
| 2 | 5 | 5 / 2 | Очень просто | 60 мс |
| 3 | 8 | 5 / 3 | Просто | 80 мс |
| 4 | 10 | 6 / 3 | Просто | 100 мс |
| 5 | 12 | 7 / 3 | Средне | 120 мс |
| 6 | 15 | 6 / 4 | Средне | 150 мс |
| 7 | 17 | 7 / 4 | Сложно | 200 мс |
| 8 | 19 | 8 / 4 | Сложно | 250 мс |
| 9 | 22 | 9 / 4 | Очень сложно | 350 мс |
| 10 | 24 | 9 / 4 | Очень сложно | 400 мс |

Кривая использует только рейтинги 1, 3, 4, 6, 7, 10 — остальные заданы про запас (для дев-панели и будущих правок кривой).

Лейбл в HUD считает `Render.getDifficultyByRating(rating)` — **по замыслу уровня**, а не по факту BFS. Старый путь `getDifficulty(optimalSteps)` остался для сейвов, сделанных до перехода на кривую, и для раскладок из дев-панели (у них рейтинга нет).

## Как генерируется уровень

`Levels.generateForTarget(params)`:

1. Сэмплим случайную раскладку на поле пресета (`randomLayout`).
2. Меряем BFS-оптимум (`Solver.findShortestPath`, потолок 120 мс на кандидата).
3. Нерешаемые и не уложившиеся — пропускаем.
4. Держим лучшего кандидата по `|оптимум − цель|`, при точном попадании выходим сразу.
5. Ограничители: `maxAttempts` (детерминированный потолок) и `budgetMs` (страховка на медленном устройстве) — что наступит раньше.

**Фолбэк**: если ни одной решаемой не нашли — отдаём раскладку обратным перемешиванием из решённого состояния (`reverseShuffleFromSolved`). В замерах не понадобился ни разу.

### Замеренное качество

Прогон настоящего кода на 200 уровнях подряд: **200/200 точных попаданий в цель**, средняя `|Δ|` = 0.00, ни одного фолбэка, суммарно 1.6 с, худший отдельный уровень 142 мс. По рейтингам на 25 разных сидах: 1–7 попадают точно всегда, 8–10 — среднее отклонение < 0.4 хода.

## Почему именно так (замеры)

Ключевое наблюдение: **при одной пустой колбе большинство случайных раскладок нерешаемы, но BFS отбраковывает их за единицы миллисекунд**, а те, что решаемы, дают предсказуемый оптимум. Это делает «сэмплирование + BFS» дешёвым.

Случайные раскладки, 1 пустая колба (оптимум решаемых / стоимость находки):

| поле | оптимум p25–p75 | мс на одну решаемую |
|---|---|---|
| 3/2 | ровно 3 | 0 |
| 5/3 | 7–8 | 0 |
| 6/3 | 8–11 | 0 |
| 6/4 | 14–16 | 0 |
| 7/4 | 17–18 | 1 |
| 8/4 | 19–22 | 3 |
| 9/4 | 23–25 | 11 |
| 10/4 | 27–28 | 40 |
| 11/4 | 29–33 | 143 |
| 12/4 | 33–35 | 735 |

Что **не** сработало и почему:

- **Обратное перемешивание из решённого состояния** (V1) как основной генератор: даёт 100 % решаемость и мгновенный BFS, но оптимум упирается в потолок ≈ 13–16 ходов на средних полях и ≈ 19 на 12 колбах — тяжёлый конец шкалы недостижим. Причина: прямой ход переносит весь ран целиком, поэтому разбросанные одиночные фишки собираются обратно за считанные ходы.
- **Две пустые колбы**: решаемость почти 100 %, но ветвление растёт, и BFS дорожает на порядки (медиана 78–308 мс, на части полей вообще не укладывается в 300 мс). Для генерации на лету не годится.

Скрипты замеров одноразовые, в репозиторий не клались; методика описана выше и воспроизводится за пару минут (извлечь `window.Solver` из `index.html`, прогнать выборку раскладок).

## Параметры уровня

| Поле | Тип | Описание |
|---|---|---|
| `level` | int | Номер уровня |
| `rating` | int 1–10 | Рейтинг кривой; определяет лейбл сложности |
| `sticks` | int | Всего колб (включая пустую) |
| `capacity` | int | Слоёв в колбе |
| `emptyStick` | int | Пустых колб (кривая всегда ставит 1) |
| `colours` | string[] | Имена цветов из `Levels.PALETTE`, ровно `sticks − emptyStick` |
| `difficulty` | int | **Цель**: длина оптимального решения |
| `generator` | `'target-tuned'` \| `'random-tuned'` \| `'reverse-shuffle'` | Алгоритм |
| `budgetMs` / `maxAttempts` | int | Потолки подбора для `target-tuned` |
| `seed` | int | Зерно PRNG (детерминизм до генерации) |
| `bottles` | string[][] | Опционально: готовая раскладка, генератор не вызывается |

`Levels.getParams(n)`: runtime-override дев-панели → сохранённый custom-уровень → `DEFAULT_LEVELS[n-1]` (первые 24 уровня кривой, материализованы для дев-панели) → `curveParams(n)` на лету.

## Палитра

`Levels.PALETTE` + CSS-переменные `--c-<name>`:

```
pink, orange, yellow, lime, teal, blue, purple, crimson, cyan, mint, coral
```

Чтобы добавить цвет: вписать имя в `PALETTE`, добавить `--c-<name>` в `:root` и hex в `COLOR_HEX` (зеркало палитры для inline-SVG).

## Генераторы

- **`target-tuned`** — основной, описан выше.
- **`reverse-shuffle` (V1)** — обратные ходы из решённого состояния. Быстрый, почти всегда решаемый, но потолок сложности низкий. Используется как фолбэк и в дев-панели.
- **`random-tuned` (V2)** — случайные раскладки + BFS до совпадения с `difficulty` в пределах `tuningTimeoutMs`. Остался для дев-панели; `target-tuned` — это он же, но с бюджетами под мгновенную генерацию и без режима `requireBonus`.

## Как менять баланс

- **Форма кривой** — `CURVE_PREFIX` / `CURVE_CYCLE`.
- **Что означает рейтинг** — `RATING_PRESETS[r].moves` (число ходов) и поле `sticks/capacity`.
- **Скорость генерации** — `budgetMs` / `maxAttempts` в том же пресете.

Меняя поле под рейтинг, сверься с таблицей замеров выше: цель должна попадать в диапазон p25–p75 этого поля, иначе подбор будет долгим или неточным.

## Дев-панель (5 тапов по «Уровень N» или `Ctrl+Shift+D`)

Форма поверх игры: `Колбочки` (sticks), `Ёмкость` (capacity), `Пустых` (emptyStick), `Цвета`, `Генератор`, `Сложность` (целевые ходы), `Тайм-аут`, `Seed`.

- **🎲 Сгенерировать** — применяет параметры к текущему уровню как runtime override (в памяти, теряется при reload). В статусе: `attempts=N, solvable=N, optimal=N, distance=N ✓, Xms`.
- **💾 Сохранить override** — в `localStorage.customLevels[N]`, переживает reload и подменяет уровень кривой.
- **↺ Сбросить override** — удаляет runtime и persistent override.
- **📋 Copy JSON** — конфиг в буфер обмена.

Чтение статуса: `distance = |optimal − difficulty|`, `0 ✓` — точное попадание. Если `distance > 0` — подними тайм-аут или поменяй поле.

Дев-панель целиком вырезается из release-сборки маркерами `HTML2APK:DEV_ONLY`.
